1. 项目概述

Crown Rush（百关闯关）是以「投注累积经验值 → 闯关成功 → 领取奖励」为核心的长周期留存活动。活动共 100 个关卡，关卡奖励以现金为主，在 8 个里程碑关卡配置限量实体大奖。活动包含三个前台页面（活动预热页、活动进行中页、活动结束页）与一套运营后台配置能力，三页按活动状态自动切换。

项目说明
活动周期以自然月为一期，示例期 12/01 00:00:00 - 12/31 23:59:59（GMT+8）
目标用户全体已注册真实用户，支持后台配置准入条件
页面状态机pending（预热页）→ running（进行中页，12/01 00:00:00 自动切换）→ ended（活动结束页，12/31 23:59:59 自动切换）。状态以服务端时间为准，前端倒计时归零后需请求活动状态接口确认再切页
核心指标活跃留存、日均有效投注、活动参与率、实体奖品曝光转化、奖励领取率
语言当前原型三个前台页面均为中文；正式上线的前台语言（英文 / 中英双语）待运营确认，后台为中文

2.3 物流信息修改流程

用户点击「修改地址」 → 系统向账号绑定手机号发送短信验证码 → 用户输入验证码校验通过 → 前台开放编辑表单 → 用户自行修改并保存 → 系统记录修改日志（时间 / 修改前后值 / 设备） → 前台展示更新后的物流信息。奖品已进入发货流程时地址冻结，此时才需联系客服。

2.4 系统时序（后端视角）

每小时定时排行榜任务重算 TOP 100 并写入缓存，剔除风控标记账号

新一期开启活动服务归档上期数据 → EXP 与关卡进度全量清零 → 上期未领取奖励失效 → 所有用户从第 1 关 0 EXP 重新开始

3. 业务规则

3.1 经验值（EXP）

  • EXP = 有效投注额 ÷ 游戏类型流水权重；老虎机 1:1，真人娱乐场 20:1（权重由后台配置）。
  • 仅统计活动周期内、参与游戏范围内的有效投注；取消注单、对冲注单不计入。
  • EXP 实时累计，用户无需报名。
  • 跨期清零：活动以自然月为一期，新一期开启时 EXP 全部清零、关卡进度不继承，下一期所有用户统一从第 1 关、0 EXP 重新开始；上一期已领取的奖励不受影响，未领取的奖励在新一期开启时失效（活动结束至新一期开启之间为领奖缓冲期，可随时领取）。

3.2 关卡

  • 共第 1 关 - 第 100 关，每关配置累计投注门槛与对应奖励；EXP 达标即闯关成功，关卡只进不退。
  • 可跨关闯过（单笔大额投注可一次连闯多关），跳过的关卡奖励仍可补领。

3.3 奖励

  • 现金奖励：闯关成功后需在活动页手动领取，支持「一键领取现金」批量领取全部已闯关成功的现金关卡，领取后即时存入账户余额。一键领取不包含实体奖励关卡，实体关卡必须在各自条目单独领取并完成物流校验。
  • 实体奖励：绑定 8 个里程碑关卡，每个关卡对应一件实体奖品（不附带现金）。限量发放、先到先得。当某关卡的实体奖品库存领完后，后续闯过该关卡的用户不再展示实体奖品，该关卡自动转为「彩金奖励」：卡片降级为普通关卡样式，文案显示「实体奖品已领完 · 改发彩金 ₱X」，领取即现金入账，且可参与「一键领取现金」。彩金替代金额由后台按关卡单独配置。
  • 领取时限：活动结束后进入领奖缓冲期，页面自动切换为活动结束页，已闯关卡的未领取奖励不设截止时间，可随时领取；新一期开启时上期未领取的奖励失效（届时如需设定明确截止日，由后台配置并在结束页统一展示）。
  • 提现打码要求（前台不展示）：用户领取的任何奖金（含关卡现金、彩金替代）均需完成该笔奖金 1 倍的打码量后方可提现。此规则不在预热页、进行中页及规则弹窗中展示，前台不做任何提示，由后台在钱包侧静默计算与拦截。

3.4 风控

如发现对冲、套利、同设备/同 IP 多账号等异常行为，平台有权取消参与资格并回收已发放奖励。实体大奖发放前需人工复核。

4–6. 前台页面

前台活动页（预热页、进行中页、结束页）的全部内容已在 v1.0 完成开发并上线，本迭代无前台页面改动，前台需求详见 v1.0 PRD 第 4–6 章。本迭代后台改动若影响前台展示数据（如剩余名额、机器人扣减），由后端接口保证数据正确，前端无需调整。

7. 运营后台需求

后台入口为「活动中心 › 流水闯关活动」，按活动配置顺序包含五个模块：奖品管理 → 活动管理 → 机器人管理 → 奖品领取记录 → 活动数据列表，进入后默认显示「活动管理」。所有金额显示千位符与 ₱ 符号；所有时间输入均使用日历卡片选择（GMT+8）。原型见《后台 · 流水闯关活动》。

公共能力说明
顶部提示栏在平台原有提示项后增加「待派发奖品：N」，N 为所有活动中状态为「待确认库存」的实体奖品记录数；点击数量跳转至「奖品领取记录」并自动筛选该状态的记录。
帮助提示操作按钮、非常见数据项及新增 / 编辑弹窗中的字段（活动状态、各时间节点、关卡数、参与游戏 / EXP 权重、物流快递预留、活动总预算、领取结果弹窗关闭秒数、单件成本、库存变动各字段、快递公司与单号、修改原因等）旁显示「?」图标，点击弹出该项的含义、计算方式或操作规则（内容见 7.9 帮助提示内容）。
操作日志启停活动、修改配置、库存变动、改奖、批量操作等均记录操作人与时间。

7.1 奖品管理

奖品管理不区分活动，统一管理平台实体奖品的库存；平台彩金 / 现金奖励不在此管理。活动关卡配置实体奖品时，只能从奖品管理中选择，且分配数量不得超过该奖品的可分配余量。

功能说明
奖品列表字段：奖品编号、奖品名称、单件成本、在库量、已分配到活动、预占、已出库、可分配余量、分配明细（各活动分配数量）、状态、操作。
新增 / 修改奖品名称、单件成本。修改时名称与在库量不可修改；单件成本修改后只影响之后发生的领取与预算核算，历史活动成本不变（活动按创建时的成本快照核算）。
库存变动填写「新增库存数量」，在当前在库量基础上累加。仅可输入非 0 整数，正数为进货入库，负数为报损等减少；负数时备注必填。调整后在库量不得小于「预占 + 各活动剩余名额」。
库存记录记录时间、类型、数量、对应活动、变动后在库量、操作人、备注。类型：入库 / 出库（报损）/ 分配至活动 / 释放分配 / 领取预占 / 预占释放 / 发货出库 / 退货入库 / 成本调整。
奖品图片：后台不提供任何奖品图片的上传与管理。前台奖品图片由设计提供、前端随版本内置，按奖品名称对应显示；新增奖品需同步提供图片并随发版上线。

7.2 活动管理

功能说明
活动状态未开始：前台不显示活动页；预热中：前台显示预热页；进行中：前台显示进行中页；领奖缓冲：前台显示活动结束页；关闭：前台不显示。列表可直接开启 / 关闭活动，也可在修改活动中直接修改状态。
创建 / 修改活动活动名称、预热开始 / 活动开始 / 活动结束时间（日历卡片，精确到秒）、关卡数、活动状态、物流快递预留（直接输入金额，位于活动总预算上方）、活动总预算。
关卡列表详情填写关卡数后可查看：每关 EXP 标准、奖励类型（实体奖品 / 彩金）、奖励内容。实体奖品只显示名称，从奖品管理选择并校验可分配余量；彩金关卡设置金额与预计领取人数（显示该关预计支出）。
库存耗尽替代实体关卡可设置库存耗尽后的替代：彩金替代（金额与预计领取人数跟随彩金批量规则）/ 无奖励 / 其他实体奖品（显示该奖品当前可分配余量）。
达标处理彩金关卡与彩金替代均可设置「预计领取人数达标后」继续领取或停止领取；支持批量统一设置。
批量设置① 每隔 N 关设为实体奖品（N 可设置）；② 彩金金额：统一金额（默认）/ 倍增（设置第一关与最后一关金额）/ 指数递增（设置第一关金额与增长指数）/ 按阶段（每阶段可选统一、倍增或指数）；③ 彩金预计领取人数：统一 / 按规则递减 / 按阶段（默认未设置）；④ 达标处理统一设置。
游戏权重配置列表操作栏进入，展示平台全部游戏分类，勾选本活动参与的分类并设置对应 EXP 权重。
活动总预算按关卡配置自动计算默认值（公式见 7.8），活动进入「进行中」之前可手动修改；手动修改后显示「手动」标记，可一键恢复自动值。预算核算逻辑待运营确认。

7.3 机器人管理

功能说明
选择活动选择活动后读取该活动每个关卡的奖励内容；可筛选只显示实体奖励 / 只显示彩金奖励 / 全部，显示彩金时可再按金额区间筛选。
关卡机器人配置每个关卡设置机器人比例与取整方式（向上取整 / 向下取整）。彩金关卡以真实领取人数为计算基数，实体关卡以该关卡实体库存总量为计算基数；计算结果不足 1 名时按 1 名计算。
机器人领取逻辑机器人领取不产生奖品领取记录，后台不需要人员处理；前台对应关卡的剩余名额随之减少。库存上：扣减该活动对应奖品的分配名额，扣回的名额恢复至平台奖品总库存中未被活动占用的部分（可分配余量 +1），在库量不变，不产生预占、出库与物流。凡涉及机器人领取的数据（库存记录、奖品分配、成本、数据列表中的领取数 / 人数等）均须标识为「机器人」数据，不计入真实成本与各项真实统计；需要时可单独查看机器人数据。
保存与重置按活动独立保存；切换活动时未保存的修改暂存，重置恢复为上次保存的配置。

7.4 奖品领取记录

功能说明
筛选与列表按活动名称、用户名、奖品类型、状态筛选。字段：记录编号、活动名称、用户名、关卡、奖品类型、奖品内容、领取时间、收件人 / 手机号、收货地址、快递单号、状态、操作。
状态流转实体：待确认库存 → 待发货 → 已发货 → 已签收，拒收 / 退回为「已退回」；现金 / 彩金：领取即「已到账」。
确认库存只核实实物库存，不扣减数量，状态改为「待发货」。在库量为 0 时弹窗「该奖品目前无库存，请确认库存！」，可修改奖品。
修改奖品仅「待确认库存」可修改；确认库存后奖品锁定。可选范围：可分配余量 > 0 的实体奖品；无库存时还可改为现金奖励或彩金奖励（填写金额，保存后状态「已到账」）。需填写修改原因。原奖品释放预占，新实体奖品预占 1 件。
修改物流仅「待确认库存」「待发货」可修改；发货后不可修改。
发货单条发货或导入快递单号：预占 −1、已出库 +1、在库量 −1，写入「发货出库」记录，状态「已发货」。
拒收 / 退回「已发货」「已签收」可登记：已出库 −1、在库量 +1，写入「退货入库」，并从原活动分配中扣回 1 件——奖品回到平台可用库存，状态「已退回」。
导出 / 导入导出仅包含奖品类型为「实体」且状态为「待发货」的记录，文件为 Excel 可读写格式，文件名含导出时间、导出人、活动名称。导入仅更新填写了快递单号的「待发货」记录：写入快递单号并改为「已发货」，同时出库；其他记录不更新并在结果中逐行说明原因。
批量操作勾选「待确认库存」「已发货」记录，支持「批量确认库存」（待确认库存 → 待发货，校验在库量）与「批量确认签收」（已发货 → 已签收）。执行前弹出二次确认，可取消勾选部分记录；执行后显示本次处理 / 成功 / 失败数量及逐条失败原因，失败与未勾选记录保持原状态。
库存时间差控制：用户领取即预占、确认库存只核实、发货时才出库，保证领取到发货期间账面与实物一致；前台领取只校验活动剩余名额，不依赖后台处理，互不阻塞。系统须保证同一用户同一关卡只生成一条领取记录（幂等）；「待确认库存」超 24 小时、「待发货」超 72 小时在后台告警提醒；每日自动对账，行政定期盘点，差异通过入库 / 报损调整并留痕。

7.6 活动总预算与成本口径

实体奖品成本按领取发生时的单件成本核算（活动创建时生成成本快照，单件成本调整不追溯）；物流快递按活动配置的预留金额计入预算，实际发生额按发货件数核算；彩金替代与现金奖励按实际发放金额计入。机器人领取的彩金与实体均不计入成本、预算使用率及各项真实统计。

数据项 / 操作说明内容
公共
待派发奖品所有活动中状态为「待确认库存」的实体奖品记录数量。点击数量可跳转到奖品领取记录并自动筛选这些记录。

现金 / 彩金：领取即「已到账」。
确认库存后不可修改奖品，发货后不可修改物流信息。
奖品管理
在库量仓库中实际存放的件数。只在入库、报损、发货出库、退货入库时变化；用户已领取但尚未发货的奖品仍计入在库量。
已分配到活动各活动关卡配置中为该奖品设置的名额之和。名额被占用后不能再分配给其他活动或用于改奖。
预占用户已在前台领取、尚未发货的件数（待确认库存 + 待发货）。
领取时即预占 1 件；改奖或改为现金 / 彩金时释放；发货时转为出库。
已出库已发货出库的累计件数。拒收 / 退回登记后相应减少，并退回在库量。
可分配余量可分配余量 = 在库量 − 预占 − 各活动剩余名额。
可用于新活动的关卡分配，或领取记录中的修改奖品。
单件成本用于活动预算与成本核算。修改后只影响之后发生的领取与预算，历史活动已核算的成本不变。
新增库存数量在当前总库存基础上累加。只能填非 0 整数：正数为进货入库；负数为报损等减少，此时备注必填。
调整后总库存自动计算：当前总库存 + 新增库存数量。不得小于「预占 + 各活动剩余名额」。
备注记录本次库存变动的原因，会写入库存记录。新增库存数量为负数时必填。
活动管理
活动状态未开始：前台不显示活动页；预热中：前台显示预热页；进行中：前台显示进行中页；领奖缓冲：前台显示活动结束页，只能领奖不再累计 EXP；关闭：前台不显示。修改后前台按新状态切换页面。
预热开始时间到达该时间后活动自动进入「预热中」，前台显示预热页与开始倒计时。
活动开始时间到达该时间后自动进入「进行中」，前台预热页自动切换为进行中页，开始累计 EXP。
活动结束时间到达该时间后自动进入「领奖缓冲」，前台切换为活动结束页：停止累计 EXP，已闯关未领取的奖励仍可领取。
关卡数本活动的关卡总数。填写后可点击「查看关卡列表详情」配置每关的 EXP 标准与奖励。
参与游戏 / EXP 权重勾选计入本活动 EXP 的游戏分类，并设置每个分类的权重。EXP = Σ（各分类有效投注 ÷ 权重），例如权重 20 表示每 ₱20 有效投注累计 1 EXP。
物流快递预留预算直接输入金额，作为实体奖品物流快递费用的预留，计入活动总预算。输入框下方会显示建议值（实体成本的 5%）供参考。
活动总预算默认按关卡配置自动计算：彩金 + 彩金替代 + 实体奖品成本 + 物流快递预留。
活动进入「进行中」之前可手动修改；具体核算逻辑待运营确认。
领取结果弹窗关闭秒数前台「一键领取」结果弹窗的自动关闭倒计时，默认 30 秒。
库存耗尽替代 / 达标处理库存耗尽替代：实体奖品领完后，该关卡改发彩金、换其他实体奖品或无奖励。
达标处理：预计领取人数达标后，该关卡继续领取或停止领取。
机器人管理
机器人领取逻辑机器人按每关设置的比例与取整方式触发领取：
· 不产生奖品领取记录，后台无需人员处理；
· 前台对应关卡的剩余名额随之减少；
· 实体关卡扣减该活动的分配名额，名额回到平台未被活动占用的库存（在库量不变，不产生预占、出库与物流）；
· 所有相关数据标识为「机器人」，不计入真实成本与真实统计。
机器人领取数按「计算基数 × 机器人比例」并按所选方式取整得出的机器人领取数量，不足 1 名按 1 名。该数量只影响前台剩余名额与活动分配，不生成领取记录。
当前基数彩金关卡为该关当前真实领取人数（不含机器人）；实体关卡为该关当前实体库存总量（活动分配名额）。
机器人领取（彩金）统计期内机器人领取彩金的次数。标识为机器人数据，不计入现金发放、活动成本、预算使用率与领取人数等真实指标。
机器人领取（实体）统计期内机器人领取实体奖品的件数。每件扣减该活动分配名额并回到平台可分配余量，不消耗实物，不计入实体领取、实体成本与履约数据。
机器人比例按关卡设置机器人领取占比。
彩金关卡：按该关卡真实领取人数 × 比例计算机器人数量；
实体关卡：按该关卡实体库存总量 × 比例计算。
取整方式机器人数量计算结果不是整数时的处理方式：向上取整或向下取整。计算结果不足 1 名时按 1 名计算。
计算基数机器人数量的计算依据：彩金关卡为真实领取人数，实体关卡为该关卡实体库存总量。
奖品领取记录
导出领取记录只导出奖品类型为「实体」、状态为「待发货」的记录（可按活动筛选）。在导出文件中填写快递公司与快递单号后，通过「导入快递信息」上传。
导入快递信息上传填写好的导出文件：只更新填写了快递单号的「待发货」记录，写入单号并改为「已发货」，同时出库（预占 −1、在库量 −1）。未填单号或其他状态的记录不更新。
批量确认库存对勾选的「待确认库存」记录批量核实实物库存。执行前可在二次确认中取消部分记录；在库量为 0 的记录会失败并保持原状态。
批量确认签收对勾选的「已发货」记录批量改为「已签收」。执行前可在二次确认中取消部分记录。
快递公司选择承运快递公司，与快递单号一起同步给用户。
快递单号填写后状态改为「已发货」，同时出库（预占 −1、在库量 −1），用户可在前台查看物流信息。
修改原因修改用户物流信息须填写原因，记录在操作日志中。发货后不可再修改物流信息。
活动数据列表
EXP 权重有效投注折算 EXP 的比例，例如「1 EXP / ₱20」表示每 ₱20 有效投注累计 1 EXP。在活动的「游戏权重配置」中设置。
活跃率活跃率 = 该游戏分类活跃用户数 ÷ 活动参与人数。同一用户可同时活跃于多个分类，各分类之和可能超过 100%。
日均活跃用户统计期内每天在该游戏分类产生有效投注的去重用户数的平均值。
平台毛收益（估算）平台毛收益 = 各游戏有效投注 × 对应抽水率（示例：老虎机 5%、真人 1.2%）。抽水率口径待财务确认。
净收益净收益 = 平台毛收益 − 活动总成本（现金奖励 + 彩金替代 + 实体奖品成本 + 物流快递）。
ROIROI = 净收益 ÷ 活动总成本，用于衡量每投入 ₱1 活动成本带来的净收益。
单用户获客成本单用户获客成本 = 活动总成本 ÷ 新增参与人数（首次参与本活动的用户）。

8. 数据埋点需求

8.1 分析目标

  • 拉新与触达：预热期各渠道进入量、预热页到活动页的承接率。
  • 激活转化：浏览 → 首次投注（首次获得 EXP）→ 首次闯关成功 → 首次领取的漏斗转化。
  • 留存与深度：日活跃参与人数、人均闯关数、关卡分布与卡点（哪一关流失最多）。

  • 导流效果：热门推荐 / 先行热身 / 热门活动各位置的点击与后续投注贡献。

  • 所有领取类事件携带 order_id 做幂等去重，与钱包流水可对账。
  • 曝光事件做节流：同一模块同一次页面会话内只上报一次，滑动类事件合并上报间隔 ≥500ms。
  • 未登录用户以设备 ID 归因，登录后需回溯绑定 user_id，保证漏斗可串联。
  • 打码量规则相关的任何字段与提示均不得下发至前端，仅在服务端与看板内部使用。
  • 事件命名统一前缀 cr_，上线前需与数据团队确认埋点文档版本与测试环境校验通过。

9. 接口与异常

  • 核心接口：活动信息、用户进度、关卡任务列表、领取（单项/一键）、领奖记录、排行榜、物流信息提交与查询、验证码发送与校验。
  • 领取接口需幂等，防止重复领取；实体奖品领取需库存原子扣减。
  • 异常态：未登录、活动未开始/已结束、库存售罄、领取失败、网络异常，均需前端明确提示文案。
  • 活动状态接口：返回 status（pending / running / ended）、server_ts、本期起止时间与下一期信息。前端在倒计时归零、页面进入前台、以及每 60 秒轮询时调用；切页一律以该接口为准，不得仅依赖本地倒计时。
  • 结束态接口差异：进度接口在 ended 状态下返回封存后的最终 EXP 与最终关卡（不再随投注变化）；关卡任务接口仅返回已闯过的关卡；实体奖品接口仅返回用户已闯过的奖品关卡；榜单接口返回封存的最终排名。
  • ended 状态下仍需支持：单项领取、一键领取现金、物流信息提交 / 查询 / 修改、短信验证码、领奖记录查询。

10. 待确认事项

  1. 热门活动位的真实活动清单、金额与跳转链接（当前为占位内容）。
  2. 游戏封面图资源与各游戏列表页的最终 URL 路径。
  3. 实体奖品的实际库存数量与物流承运方案。
  4. 结束页是否需要设定明确的领奖截止日（当前按「无截止、新一期开启时失效」实现）。
  5. 结束态主视觉素材是否单独出图。
  6. 正式上线的前台语言（中文 / 英文 / 双语）。

11. 各角色协作 Tips

以下为结合本项目特点（长周期、强奖励、限量实体奖品、多弹窗流程、菲律宾本地市场）给各角色的实操建议，非硬性需求，但能显著减少返工与线上风险。

UI / 视觉设计
  • 先定关卡卡片的状态矩阵：未闯关 / 可领取 / 已领取 / 实体关卡 / 实体售罄降级，共 5 种，一次出全比事后补状态省时。
  • 进度条内文字必须与填充色互补：本项目踩过「绿字压绿条」的坑，凡是条内标签都要同时校验 0% 与 100% 两个极端的对比度（≥4.5:1）。
  • 节日素材统一走透明底 PNG：奖品图、主视觉、装饰件都需抠底并裁至主体，切图前先确认最终渲染尺寸，按 2-3 倍导出即可，避免上传 1700px 原图导致弹窗白屏。
  • 弹窗按「高度预算」设计：主视觉 + 金额 + 列表 + 按钮的总高必须在 75-90% 视口内闭合，列表条数用固定值（如 5 条）而非「自适应」，否则小屏必然挤掉按钮。
  • 菲律宾本地化元素要真实而非符号化：Parol 星灯、Maligayang Pasko 问候、₱ 货币符号优于泛化的圣诞树图标；同时避免过度装饰压住核心信息。
  • 为空态与售罄态出图：「暂无可领取的现金奖励」「已领完」「未登录」这三种状态最容易被漏掉，却是用户高频看到的界面。
前端开发
  • 活动状态一律以服务端为准：倒计时仅用于展示，归零后必须请求活动状态接口再切页，防止本地改时间提前进入。
  • 领取按钮做防抖 + 幂等：一键领取与单关领取都要禁用二次点击并携带 order_id，网络重试不能造成重复入账。
  • 弹窗层级与滚动隔离：物流填写 → 二次确认 → 短信验证三层弹窗会叠加，需统一 z-index 规范并锁定背景滚动。
  • 列表滚动定位用 scrollTo 而非 scrollIntoView：容器内定位到「首个未领取关卡」时，scrollIntoView 会带动整页跳动。
  • 装饰动效走 transform / opacity：飘雪、雪橇、脉冲都用 GPU 属性，避免 top/left 动画在中低端安卓机上掉帧。
  • 图片资源按渲染尺寸出：弹窗内 70px 高的图不要引用 560px 以上的源图，首屏与弹窗素材建议预加载。
  • 打码规则相关字段绝不接入前端：接口若返回也需忽略，避免被抓包反推规则。
后端开发
  • 库存扣减必须走分布式锁或数据库行锁：8 个里程碑关卡是典型秒杀场景，先锁定名额再生成工单，超时未完成则释放。
  • EXP 计算与注单结算解耦：用消息队列消费注单，支持重放与补算；取消注单、对冲注单需可回退 EXP。
  • 关卡只升不降：EXP 回退时保留已达成关卡与已领奖励，避免用户资产被回收引发客诉。
  • 彩金替代金额与打码倍数做配置化：不要写死在代码里，运营需要在活动中期调整。
  • 物流信息修改留全量日志：时间、修改前后值、IP、设备、验证码校验记录，便于风控与客服追溯。
  • 验证码接口做频率与次数限制：同手机号 60 秒一次、单日上限、连续失败锁定，防短信轰炸与撞库。
  • 榜单用缓存 + 定时计算：TOP 100 每小时刷新即可，不要实时查库；同时为「我的排名」单独提供轻量接口。
测试
  • 时间类用例优先：活动开始前 1 分钟 / 归零瞬间 / 活动结束瞬间、跨时区、本地时间被改早或改晚，共 6 组必测。
  • 库存并发场景：多人同时领取最后一件实体奖品，验证只有一人成功、其余降级为彩金且金额正确。
  • 领取幂等：断网重连、重复点击、接口超时重试后核对钱包流水笔数与金额。
  • 物流三层弹窗全路径：未登录点击领取、填写中放弃、二次确认取消、验证码错误/过期/重发、绑定后再次进入应变为「查看物流信息」。
  • 降级态回归：把某关卡库存设为 0，验证列表卡片样式、文案、按钮行为、一键领取是否纳入、榜单实物列是否剔除。
  • 小屏与长文本：360×640 等小屏下弹窗按钮是否可见可点；超长用户名、超大金额（7 位数）是否截断错位。
  • 三态自动切页：预热→进行中（12/01 00:00:00）、进行中→结束（12/31 23:59:59）两个切换点；本地时间改早/改晚均应由服务端状态纠正。
  • 结束页专项：未解锁关卡不显示、EXP 停止累计、库存卡组与叠卡仅含已闯关卡、结束态仍可完成领取与物流全流程。
  • 埋点校验：按 8.3 清单逐事件核对参数完整性，重点验证服务端上报事件与前端事件不重复计数。
运维 / 运营支持
  • 活动首日与整点做扩容预案：0 点开赛、每小时榜单刷新、发薪日是三个流量尖峰，提前评估数据库与缓存容量。
  • 关键告警阈值：领取失败率 >1%、库存接口响应 >500ms、短信发送成功率 <95%、钱包入账延迟 >10s，均需即时告警。
  • 准备一键降级开关：榜单、热门推荐、热门活动等非核心模块可独立关闭，保障领取主链路。
  • 奖励发放对账每日跑批：活动侧领取记录与钱包流水按 order_id 双向核对，差异当日处理。
  • 实体奖品库存预警：剩余 ≤20% 时通知运营，提前决定补货或启用彩金替代。
  • 上线前演练回滚：活动配置、关卡奖励表支持快速回滚到上一版本；保留活动暂停能力（暂停后 EXP 继续累计但停止领取）。
  • 客服话术与后台权限先就位：物流修改、补发、异常领取三类工单的处理流程与权限边界在开赛前确认。
