1. 背景与目标

菲律宾是全球圣诞季最长的市场之一（通常从 9 月持续到 1 月初的三王节），节日氛围对用户活跃与充值意愿有明显带动。本需求将平台全站页面皮肤与桌面图标临时切换为圣诞主题，配合 12 月 Crown Rush 百关闯关等节日活动，营造统一的节日氛围。

  • 营造节日氛围，提升首页停留时长与活动入口点击率。
  • 皮肤可在后台定时开启、定时恢复，不依赖发版；后续春节、情人节等节日可复用同一套换肤机制（见第 12 节）。
  • 换肤不改变任何业务逻辑、页面结构与交互，仅替换视觉资源。

5.5 启动页与推送通知图标

  • 启动页：App 启动页换为圣诞版，平台启动页动画同步换肤；动画时长不得延长现有启动耗时，皮肤关闭后恢复默认启动页与动画。
  • 推送通知小图标：Android 状态栏通知小图标与 iOS 推送图标同步换为圣诞版。
  • 启动页、启动动画与推送图标的设计方案与交付规格由 UI 设计师确定，并与客户端开发确认；原生资源须随 12/01 前的版本一同内置。

6. 换肤机制

  • 皮肤资源包：每套皮肤由「配色变量 + 图片资源 + 装饰层配置」组成，前端按皮肤 ID 加载；未开启时使用默认皮肤。
  • 下发方式：客户端启动和进入首页时请求皮肤配置接口，返回当前生效的皮肤 ID、资源包版本与 CDN 地址；资源预下载并缓存到本地，避免首屏闪烁。
  • 定时生效：按服务端时间（GMT+8）判断，本期默认 12/01 00:00:00 开启、01/06 23:59:59 自动恢复。具体生效时间段由运营在后台自行调整（如提前到 11 月中旬或延长到 1 月中旬），无需发版。
  • 灰度：灰度比例指新皮肤先对多少比例的用户开启。例如设为 5%，只有约 5% 的用户看到圣诞皮肤，其余用户仍看到默认皮肤；设为 100% 即全量上线。
    • 目的：先让少量用户使用，确认页面无错位、加载未变慢、无明显报错后，再逐步放大到 100%；发现问题时只影响少数用户，可快速关闭。
    • 分组规则：按用户 ID 稳定分组，同一用户在灰度期间始终看到同一套皮肤，不因刷新或重新登录来回切换。
    • 支持按用户比例、渠道或端开启；本期 11/28 先放量 5% 验证，12/01 00:00 全量生效（100%）。
    • 如不需要分批上线，可直接设为 100%，皮肤到开始时间即对所有用户生效。
  • 回滚：后台停用即恢复默认皮肤，客户端下次请求时生效，无需发版。
  • 降级：资源加载失败时，该区域回退到默认皮肤资源，不能显示空白或错位。

7. 运营后台：节日皮肤管理

入口：后台「活动配置」栏目下新增「节日皮肤管理」子栏目。原型见《后台 · 节日皮肤管理》。

功能说明
筛选按皮肤名称（模糊匹配）、状态、适用端筛选；提供「确定」「重置」
皮肤列表字段：序号、皮肤名称、资源包版本、适用端、生效时间（GMT+8）、灰度比例、桌面图标（切换 / 不切换）、状态、创建人、操作
状态未开始 / 生效中 / 已结束 / 已停用；前三种由系统按当前时间与生效时间段自动计算，已停用由人工操作产生
新增 / 编辑字段：皮肤名称（必填）、资源包版本（下拉选择，必填）、适用端（H5 / PWA / Android / iOS 多选，至少一项）、开始时间与结束时间（精确到秒，必填）、灰度比例（0–100%，默认 100%）、桌面图标是否切换
保存校验结束时间须晚于开始时间；同一适用端上未停用的皮肤生效时间段不得重叠，重叠时提示与哪套皮肤冲突
启用 / 停用列表中直接操作，须二次确认；停用后客户端下次请求配置时恢复默认皮肤
操作日志记录新增、编辑、启用、停用的时间、操作人、皮肤名称与操作类型，可在列表页查看
资源来源皮肤素材与图标由前端开发统一打包上传到 CDN，后台只选择资源包版本，不提供单张图片上传
不在后台配置：换肤生效的页面范围、飘雪等动效均由 UI 设计师与前端工程师确定，并打包在资源包内，后台不提供配置项。

8. 性能与兼容

  • 皮肤资源包总体积 ≤ 1.5 MB；首屏新增资源 ≤ 300 KB。
  • 开启皮肤后首页首屏加载时间的增幅不超过 10%。
  • 飘雪等动效只用 transform / opacity 实现，低端机（内存 ≤ 3 GB）和开启了「减少动态效果」的设备自动关闭。
  • 兼容 iOS 13+、Android 8+，覆盖主流屏幕尺寸（360–430 pt 宽）。

9. 数据埋点

  • 公共参数增加 skin_id，所有页面浏览和点击事件携带当前皮肤 ID。
  • 对比指标：首页停留时长、Banner 点击率、悬浮活动入口点击率、次日留存；与 11 月同期的默认皮肤对比。
  • 图标切换：记录原生 App 图标切换成功 / 失败（app_icon_switch，含失败原因），以及用户是否拒绝 iOS 切换提示。

11. 验收标准

  1. 第 2 节所列页面与第 4 节首页各区域均按 UI 最终设计稿呈现；邀请页与活动详情页内容保持不变，各端表现一致。
  2. 后台开启 / 停用后，客户端在下一次请求配置时正确切换，不需要发版。
  3. 到达定时结束时间后自动恢复默认皮肤，不残留圣诞资源。
  4. 资源加载失败时正确回退到默认皮肤，不出现空白或错位。
  5. 按钮、余额、金额等关键信息不被装饰层遮挡，点击区域不受影响。
  6. 性能满足第 8 节指标。

12. 延展需求（非本期重点）

  • 春节、情人节等后续节日复用本期换肤机制：新增节日只需上传新的皮肤资源包并在后台配置生效时间，无需改动前端逻辑。
  • 后台支持预留多套皮肤，按时间段排期依次生效；同一端的多套皮肤生效时间段不得重叠（本期后台已做校验）。
  • 本期开发时需将皮肤资源包结构、配置接口与启动页 / 图标切换能力做成通用方案，不写死圣诞专用逻辑，为后续节日预留扩展。
